# 城市 roleplay · 第一阶段 city.1

## 已实现

- `/城市 绑定`：管理服务器权限，当前主文字频道登记为地点；街道名称分组、地点名称、类型、描述可更新。
- `/城市 地图 页码:1`：每页20个地点，仅展示调用者有权查看的频道；机器人也必须能访问。公共地点、小酒馆、店铺、住宅四种类型。
- `/城市 地点`：当前地点说明；文字子区继承父频道地点，场景对话独立。
- `/城市 进入`：当前位置登记；可指定有权查看的已登记地点频道。指定频道只移动角色记录，不操作用户客户端。
- `/城市 位置`、`/城市 离开`：角色位置与退出；30分钟未互动显示暂离。位置随进入或在已登记地点@机器人更新，浏览频道、普通聊天不更新。
- 地点对话仍由红豆粉回应，传入当前地点资料；非酒馆地点不自动触发酒馆点单/自然菜单或记录酒馆客流。
- 每个场景最多16条成功@问答记录，提供最近12条、24小时内的有效记录。个人记忆关闭时不保存本人的正文，不提供本人的旧场景问答。频道记忆默认关闭，仅接续本人在当前场景的问答；管理员开启频道记忆后，允许使用当前场景其他开启个人记忆成员的成功@问答。
- 个人记忆清除同步删除本人城市场景问答，频道记忆清除同步删除当前场景问答。绑定取消后清理该地点场景；近期记录为按访问筛选，不是后台定时删除。
- 同一服务器的钱包、物品和已有关系档案继续使用原系统；城市不新建钱包、不改变收益，不自动开放新店交易。

## 你需要配合

1. 在Discord建一个频道分类作为街道，例如“河西街”。可以直接移动已有频道到分类，不需要重建小酒馆。
2. 街道下先保留小酒馆，另建街道广场；花店等可以稍后加。主地点使用文字频道；包间用该频道的文字子区。论坛住宅集合的业务尚未接入。
3. 给机器人相应地点的查看频道、读取消息历史、发送消息权限；子区里给发送消息权限。使用斜杠命令的成员也需要相应权限。城市功能不要求管理员权限赋给bot；登记者本人需要管理服务器权限。
4. 在小酒馆频道使用 `/城市 绑定 名称:红豆粉小酒馆 街道:河西街 类型:小酒馆 描述:你希望的场景说明`。
5. 在广场频道使用 `/城市 绑定 名称:街道广场 街道:河西街 类型:公共地点 描述:你希望的场景说明`。
6. 玩家使用 `/城市 地图`，前往地点频道后 `/城市 进入`，再@红豆粉试聊。多人场景接续需要管理员在对应频道或子区使用 `/ai 频道记忆 开启`。
7. 新Slash命令可能需要Discord客户端稍后刷新。若没有入口，先确认机器人已授权应用命令并在服务器可用。

不需要提供密钥或改Cloudflare配置，也不需要把频道ID手抄给开发者。

## 当前边界与下一阶段

第一阶段是地点/场景底座，并非整个城市玩法完成。尚未实现：地图插画、自动普通聊天监听/城市史、不同店主NPC、花店商品与跨店交易、居民住宅权限分配、城市事件/任务、世界天气、玩家开店。普通聊天不保存，不声称读取全服务器历史。

下一阶段：根据实际绑定地点设计城市整体布局与视觉；再接一种新店NPC和业务，使买礼物→赠送→跨地点事件形成可验证闭环。故事和NPC创作按仓库Gemini写作流程执行。位置只是角色场景记录，不禁止玩家自由聊天，也不把点击浏览频道当作移动。

## 实现与验证

`city-service.mjs`保存配置、位置和本地场景问答，按`city:guildId`路由原有TABLES DO类，城市操作在存储事务内执行，不沿用牌桌全请求锁，也无模型/Discord网络等待。`city-ui.mjs`负责Discord命令、目标频道访问校验、私密响应与地点解析。聊天中只调用已授权渠道，没有开放公共查询API。

`/health`版本为`1.0.1-beta.92+city.1`，Gateway指纹为`chat-city1-location-context`。无D1迁移、DO迁移、新binding、secret或Cron改动。灯下迷城beta.92保持。

本地城市9项、聊天回归93项、Worker28项通过；正式CI使用现有真实字体和完整资源构建再验收。Discord手机界面和多人真人试用需上线后验证。
