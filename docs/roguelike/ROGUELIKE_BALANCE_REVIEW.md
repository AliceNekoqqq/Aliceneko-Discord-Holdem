# 第一阶段战斗数值独立审查

日期：2026-10-10（Asia/Shanghai）。范围仅为 `ROGUELIKE_CORE_SPEC.md` 与 `ROGUELIKE_FIRST_ACT_WALKTHROUGH.md` 中的基础战斗与第一幕固定牌序。以下是纸面期望值/边界推理，不是引擎模拟、随机胜率或实机测试；“杀戮尖塔2”仅作为提高规则与平衡审查严谨性的参照，不代表逐项复刻其数值。

## 结论

初始牌组有明显的情境强弱差：无护甲敌人面前，突刺的4伤害被斩击的6伤害严格压过；抢攻的8伤害以2点永久生命换取，在本轮不改变击杀阈值时未必值得付自伤，但额外伤害仍可能改变后续击杀轮数，但能跨越斩击无法跨越的击杀阈值，故不是所有局面下的严格支配。包扎在满血时效果为零，在安全战斗中则有拖延换治疗的动机。12轮上限降低但没有消除拖延治疗风险。

当前抽3选1适合 Discord 的低操作负担原型，但选择时大多数已抽牌都会被放弃，牌组增加会稀释关键牌且每轮只能打出一张；奖励若持续加牌，风险和收益都难以从固定牌序样例看出。若目标是更像多牌构筑战斗并让费用成为明确取舍，建议测试“抽4、2行动点、每轮最多打2张实体牌、费用0/1/2”的方案。这个建议是供纸面盲测的方向，不是已证实的平衡结论；牌费和初始牌费仍须先定稿。

## 可复现的算例

1. **无护甲普通敌人：**普通敌12HP、每轮玩家选一张。两张斩击各6，连续两次命中可在第二次出牌后击杀；若拿突刺替代其中一次，则两次总伤害为10，至少需第三次出牌。突刺忽略护甲只有遇到正护甲时才可能逆转比较。例如敌人有3点护甲且按每个伤害包减3，斩击造成3、突刺仍造成4；此时突刺胜出。规格未给普通敌护甲或减伤公式，因此示例里的突刺没有表现其设计价值。
2. **抢攻的临界点：**对12HP无护甲敌人，抢攻8可在一张斩击后击杀（6+8=14），而两张斩击也恰好击杀（6+6=12）。因此在这两次出牌可稳定取得、没有额外触发且两次出牌都执行的条件下，抢攻支付2生命没有缩短出牌轮数；若敌人剩7–8HP且本轮可在敌人攻击前选牌，抢攻可将敌方行动次数减少一次。对20HP Boss，示例第2轮若玩家面对Boss剩14HP，抢攻8与斩击6后Boss都还存活，但抢攻会多造成2伤并额外承受2点自伤；这个局面下它的风险回报偏差。应记录抢攻真实减少的敌方行动次数，而非只比较面板伤害。
3. **抽3选1的牌频：**完整6张牌均匀洗牌后抽3张；这些公式是完整牌组随机抽样的边际概率，不是已知剩余抽牌堆下每轮的条件概率。任一指定单张出现概率为3/6=50%；两张斩击同时出现概率为 C(2,2)×C(4,1)/C(6,3)=4/20=20%。若牌组加到9张而每轮仍抽3张，指定牌出现概率降到3/9=33.3%；若加到12张则为25%。这说明加牌本身会削弱指定关键牌的可见率，即使新牌数值不错。
4. **基础牌组每轮处理量：**每轮展示3实体，只选择1张，另外2张也入弃牌且不触发；在牌组恰为6张且无额外牌/弃牌干扰时，首两轮看完6张牌，但每轮仅打出1张。拿到包扎不等于能马上恢复：它在完整6张牌的均匀首手可见概率为50%，被选中概率还取决于该轮另两张牌、当前血量和敌方意图。固定流程中首场普通战两轮胜利，但玩家只能用两次出牌，不能据此断定实际随机对局普遍两轮结束。

## 关键风险与审查判断

- **弱牌/条件价值：**突刺在0护甲敌人前被斩击严格支配；需用覆盖有护甲敌人的战斗样例衡量。抢攻不是严格支配关系，但基础自伤是持久HP成本、攻击收益是战斗时长收益，应明确这笔交换在不同敌意图下是否值得。包扎的满血空转需要算作抽到它时的机会成本。
- **治疗刷血：**“最多12轮”避免无限循环，但未规定敌人何时击败玩家或能否在长战斗里安全地让包扎反复入手。若每次用包扎前仍能承受敌方攻击，玩家可以将敌人攻击视为换取最多3点回复的代价；真实净收益取决于敌伤、护盾和洗牌。首幕样例Boss战三轮里包扎只在第1轮出现并未被选，完全没有覆盖治疗实际选用、再洗入手牌或满血作废。建议战斗状态明确显示“本场包扎总治疗/敌方总伤害”，并加长战例核验净回血与12轮失灯的交互。
- **奖励密度/牌组膨胀：**主线路一场普通战后即加一张点燃，牌组从6涨到7；这一奖励只在Boss固定牌序里作为手工指定输入出现，不能说明奖励强度或新增牌收益。要统计每幕加牌次数、跳过奖励比例、牌组尺寸分布、关键牌入手率与通关率；固定候选奖励、删牌/治疗和奖励跳过都应进入同一测试矩阵。若一局最多多个加牌点而没有等量删牌，抽牌概率会持续下降，奖励会产生“拿到强牌却更少见到核心牌”的反直觉结果。
- **样例代表性不足：** walkthrough 明示牌序/意图是题设输入。其普通战固定两次斩击正好击杀；Boss固定点燃并重复斩击，且第三轮指定补牌格挡和点燃，抽到的包扎、突刺、抢攻都未展示有效性。样例验证了规则顺序与牌堆合法性，不提供抽牌胜率、牌的选择率、治疗价值、不同奖励方案或Boss节奏的平衡证据。
- **玩家节奏：**每轮抽3选1产生“看见很多、实际只打一张”的体验；每实体牌打出后按轮循环，牌组越大，指定牌越难找到。规则简单、按钮动作少，但可选牌常常只是三选一的单次决策，不能靠选择搭出当轮连携。

## 两种牌制比较与建议

| 维度 | 抽3选1 | 每轮抽4、2行动点、费用0/1/2、至多打2张实体牌 |
|---|---|---|
| 每轮选择 | 选一张，其余展示牌照样弃置 | 可组合打0–2张；行动点预算形成明确机会成本 |
| 牌组稀释（6张时） | 指定牌可见率3/6=50%，但只出一张 | 指定牌可见率4/6=66.7%，打出仍受行动点、费用和最多2张约束 |
| 操作/说明负担 | 低，适合单按钮交互 | 中，需显示行动点、费用及本轮已打牌数 |
| 平衡关注点 | 单牌强度、弃牌浪费、治疗拖延、加牌稀释 | 0费牌是否总是免费赚值、2费牌是否挤掉两张1费组合、抽4后组合爆发及加牌稀释 |
| 可验证性 | 容易纸算，但固定样例很容易只展示预定结果 | 每轮资源预算更容易比较同一手牌的不同组合，需先给每张牌标费 |

推荐优先做抽4/2行动点方案的纸面盲测：不做循环抽牌，不允许本轮打出的牌再次抽入；当手牌抽不满4时，按现行“抽尽后洗此前弃牌补足”的限制处理，但已在本轮手牌/已选牌实体不得重复。战斗顺序建议逐张选择/扣费/结算；第一张结算并检查胜败后，仍在战斗才允许选择第二张。也可提供组合预览，但不得提前收取后续未执行牌的生命代价。敌意图只在玩家结束本轮后执行，每张牌的自伤、伤害、治疗与终止检查点必须固定。先指定初始牌费和费用恢复规则，再评估组合；例如若斩击为1费、格挡为1费、包扎为1费，则2行动点可打斩击+格挡或两张斩击；若抢攻是0费，其2点自伤会成为额外的生命费用。这个例子只演示预算，不是最终费用建议。

抽4方案提高组合机会和指定牌可见率，预计让“每轮打一张”的损耗下降；但选择组合数增加、费用定义会引入新的强弱轴。Discord交互可以用一次组件选两张/确认，不需要增加模型调用。若团队当前优先验证最简闭环，可暂留抽3选1作为基线，但不要把它的固定演算通过描述成平衡通过。两套规则应分开跑同一组固定种子/同一敌人和奖励样本，不要在一次测试里混用两种出牌制。

## 建议采集的可检验指标

- 每张牌：被展示率、被选率、选择时的HP/敌方意图/敌人剩余HP；按敌人护甲分桶看突刺胜率与选择率。
- 每战：轮数、玩家损失HP、敌人行动次数、包扎净治疗、抢攻额外自伤、护盾溢出、失灯率；对Boss另统计各意图周期中的出牌与净生命变化。
- 构筑：战斗开始牌组尺寸、每幕新增/删除/跳过牌数、指定核心牌出现轮次、每轮抽牌重洗次数，以及奖励选择后这些指标变化。
- 抽牌制对照：在相同敌人、牌组、抽牌种子和候选奖励上，记录抽3单打与抽4双打的回合数、损血、空转牌数、每轮决策时长和规则错误率。使用多组种子与不同牌序；报告均值、中位数和分位数，避免只报总胜率。

## 未验证事项

没有运行战斗引擎或随机试验，没估算任何真实胜率。普通敌人护甲、攻击节奏、敌方HP之外的特性、各奖励池的牌数/强度分布、每幕加牌量、删除机会频率、各类额外奖励与删除机会的具体分布尚未由两个指定文件确定。抽4方案的费用恢复、逐牌结算顺序、费用不够时的选择处理也未成为现行规则；上面的2行动点例子仅用于说明测试框架。
