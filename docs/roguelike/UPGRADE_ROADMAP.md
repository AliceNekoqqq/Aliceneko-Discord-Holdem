# 灯下迷城升级规划：完整体系、选择闭环与重玩价值

制定日期：2026-10-11。基线：已上线 beta.68 / lantern-rules-v0.9。
状态：P0最小观察与P1核心机制已实现至beta.71/v0.10，具体进度见文末；P1真人退出条件尚未达成；P2第一批连接路线与补给预览已实现至beta.72/v0.11，后续资源深化未开始。

本文件作为下一轮升级入口。历史 CORE/FLOW SPEC 与 v0.5 扩充方案保留作版本参考，不能把其中旧站数、旧职业数或候选机制当作当前规则。当前事实以版本代码与 BALANCE_V09_AUDIT.md 为准。

## 1. 审视结论

现在已经有完整的单局流程：职业和难度 → 幕初遗物 → 路线 → 战斗 → 战利品 → 商店/营地/事件 → 幕末首领 → 幕间继续或撤退 → 结算、金币、进阶与每日榜 → 再开局。已有旧存档恢复、动作版本校验、结算幂等及跨服务器隔离，不需要把这些已完成基础重新做一遍。

现有规模是8职业、96张牌、31遗物、30敌人、10道具、15事件；三幕15站，回合5手牌、3能量、3次主动出牌、战斗12轮。规模足以先深化玩法。v0.9已经消除精确重复牌、重设部分职业遗物、限制灼烧升级和遗物重复触发、分开34/32/24张新牌池并取消双营地。

问题主要是“选了以后，对下一步和最终打法产生多大影响”。完整流程不等于成熟游戏；去重与调平数值也不等于耐玩。

| 维度 | 当前已有 | 实际缺口与判断 |
| --- | --- | --- |
| 构筑 | 职业起手、牌/遗物组合、升级、删牌、混搭 | 奖励候选分层抽取已有标签相关牌、本幕新牌与衔接牌；推荐另按效果权重与标签重合评分。两者仍缺少牌组缺口、发动机成熟度与实际协同的反馈。 |
| 路线 | 可预览地图、精英/危险收益、单营地、商店与契约 | 前4站主要是独立三选一，没有支路连接；选择常只改变当前站，而非下一段计划。 |
| 战斗 | 意图、条件攻击、阶段切换、反击、保留、回声、锻造与伙伴 | 三能量/三出牌使很多同费牌仍竞争同一个位置；多轮计划需要比静态效率更明显的回报。 |
| 资源 | 生命、余烬、升级、牌组厚度、道具库存 | 每种资源已有用途，但玩家未必看得懂为何删牌或留钱；营地减少后，恢复时机与构筑投资更需要可计划。 |
| 三幕 | 不同敌池、首领与新增牌 | 路线骨架相似；部分高费/复合发动机第三幕才解锁，可能没有足够战斗兑现成型体验，需要按作用重新分幕。 |
| 局后 | 金币、职业进阶、每日榜、再次开局 | 失败提示已区分耗尽生命与超时，但缺少本局构筑/关键决策回顾；重复游玩的成长主要是更高难度。 |
| 体验 | 私密面板、实时地图/战斗图、实体编号、风险提示 | 仍要检查手机阅读、目标选择和奖励操作的负担；画面美化不能替代选择深度。 |

上一轮288局仅是固定种子、固定策略的模拟，偏少逛商店和使用有代价事件。调酒师/驯兽师偏强、医师最高进阶偏弱值得跟踪；不能据此宣称真人胜率或把全部问题归为牌值。

## 2. 成品定位与闭环要求

定位：酒馆里的单人卡牌远征。每局围绕一个玩家自己形成的打法，通过读意图、选路线和管理资源，完成一段有起伏的冒险；失败后也能知道学到了什么，下一局有不同尝试目标。

先保留三幕15站、八职业及已有基础回合规则。暂不同时加入新职业、新货币、多人模式或永久战力成长。15站是否合适，最后由真实耗时和中途退出情况决定，不能凭桌面纸面规模扩成更长远征。

每个系统必须补齐：入口和条件 → 可理解的选择 → 明确代价 → 程序结算 → 可见结果 → 后续影响 → 结束/恢复状态。不能出现只有入口的收集、没有收益的升级、没有后续的事件或没有解释的失败。

| 闭环 | 完整后的玩家体验 |
| --- | --- |
| 构筑 | 我知道想形成什么打法，知道目前缺什么，奖励/商店能帮助我取舍，战斗中能看到它兑现。 |
| 路线 | 我为了治疗、升级、遗物或首领准备选择一段路线，知道因此放弃什么，后续能看见结果。 |
| 战斗 | 我能预判威胁，安排这轮和下轮的攻防，执行组合，理解实际结算和失败原因。 |
| 资源 | 拿牌、跳牌、删牌、花钱和保留道具各有情境价值，余额并非只用于结算时展示。 |
| 重玩 | 结算告诉我本局的打法和转折，发现/挑战目标提供下一局的理由，而不只是更大的敌人数值。 |

## 3. 实施顺序与里程碑

每阶段形成可独立验收的小版本，上一阶段达到退出条件再推进；同一发布不同时大改地图结构、回合上限、奖励经济与长期进度。

| 阶段 | 核心交付 | 退出条件 |
| --- | --- | --- |
| P0：观察与规则对齐 | 当前规则索引、决定原因/战斗数据采样、手机体验基线、失败分类 | 能复盘一局；能区分数值、构筑、路线、信息理解和操作失败。 |
| P1：构筑成立 | 流派角色表、奖励和推荐改造、删牌/升级反馈、发动机前移 | 每职业至少两种经过真人验证的可成型打法；玩家能解释拿牌/跳牌理由。 |
| P2：路线与资源闭环 | 真正相连的支路和汇合、补给规划、商店价值、跨站事件结果 | 同种子至少两条可行路线形成不同取舍；不出现最后才意外强迫精英的路线。 |
| P3：战斗与三幕深化 | 敌人/首领交互差异、跨轮组合、分幕压力、构筑专项平衡 | 危险有预告和应对；不同构筑改变打牌顺序和资源使用，而非只是伤害总量不同。 |
| P4a：局后反馈 | 最小本局回顾、下一局可尝试的方向 | 通关和失败均产生可解释的记录，玩家能带着明确问题重玩。 |
| P4b：可选长期目标 | 根据重玩反馈逐批加入图鉴/成就、横向起手选择、挑战目标和酒馆展示 | 无需收集即可开局；目标鼓励不同做法；每日挑战保持同题公平。 |
| P5：整体验收与打磨 | 手机交互/视觉统一、全组合边界审查、引导和可用性回归 | 功能完整、旧局可恢复、无已知软锁；真人愿意多局尝试不同打法。 |

P0的最小记录/可用性检查先完成；详细视觉、自动推荐、图鉴等在相应阶段逐步接入，不把所有观测功能当作P1的巨大前置工程。

### P0：先把问题分清楚

- 对齐旧 CORE/FLOW SPEC 与当前 v0.9 的差异，建立唯一当前规则索引；程序结果是权威，说明与图片共用同一效果数据。已有幂等、隔离和版本回归继续保留。
- 记录游戏内选择：候选与实际拿取/跳过、升级/删牌/商店消费、营地位置与选择、道具使用、战斗轮数与失败原因、首领阶段、退出地点。仅采集必要游戏动作与聚合结果，不采集聊天正文；保持日志与存储有界。
- 原始行动采样暂定保留14天，仅项目维护者可访问；到期删除或转成无法定位个人行动的汇总，公开页面只展示聚合结果。这是待实现的数据边界，不代表已配置清理任务。
- 为关键效果记录实际输出：直伤/灼烧、有效挡伤、实际治疗与溢出、锻值兑现、伙伴吸收、回声与保留使用。区分实际效果和纸面效果，不能把满血治疗、溢出盾或没兑现的备势等额记为收益。
- 先做6—10名不同熟练度玩家的小型体验观察，并在资源允许时扩样。询问为什么选路、为什么拿牌、哪里卡手、哪里看不懂、愿不愿再来一局。此规模用于发现问题，不用于宣布统计显著。
- 不把低通关率等同于弱职业：分别核对死亡、12轮超时、构筑没形成、缺补给、误读意图及操作退出。

### P1：先让96张牌形成体系

每条成熟流派列清：核心打法、铺垫/发动机、兑现/终结、防御与资源补充、选择整理、缺点和应对。缺一环时先重组现有牌/遗物和掉落时机，确认无法补齐才新增内容。

下表是验证方向，不是16套已经成型或已平衡的承诺：

| 职业 | 方向一 | 方向二 | 必须解决的张力 |
| --- | --- | --- | --- |
| 提灯旅人 | 穿甲追猎 | 备势快攻 | 当下伤害与为下一次直伤铺垫的取舍。 |
| 守门人 | 格挡反击 | 盾转伤突击 | 不能既无代价保留全部盾又兑现全部攻击。 |
| 调酒师 | 持续灼烧 | 火盾反击 | 持续压制须有时间成本，面对净化应有替代输出。 |
| 信使 | 择弃紧凑牌组 | 保留爆发 | 整理要提高关键牌兑现率，0费仍受出牌次数限制。 |
| 钟楼匠 | 备势连击 | 回声攻防 | 回声的下一轮收益与本轮生存、有限次数竞争。 |
| 医师 | 治疗护盾 | 净化追猎 | 治疗不能只延迟死亡；必须能在轮数上限内推进胜利。 |
| 驯兽师 | 伙伴护航 | 命令爆发 | 伙伴生命需要兼顾挡伤与命令可用性，不能长期无成本吸收。 |
| 铸器匠 | 持续锻造 | 武器与盾转伤混搭 | 锻造启动时间与即时攻防竞争，不能一味延后成型。 |

具体升级：

1. 牌和遗物增加设计用途信息：启动、兑现、防御、循环、衔接。用途由真实效果验证，不能只靠中文标签重合判定协同。
2. 战利品提供“当前打法的补强”“可转型/混搭”“本幕新选择”的实际取舍；保留至少一张当前幕新牌的保障。可允许构筑偏好影响候选，但能改变方向、自由跳牌，避免必定发指定组件。
3. 推荐说明只讲可靠事实，例如“可利用你已有的锻值”；不得把静态评分称为最优解。缺少有效推荐时允许不推荐。初期可用易解释的规则，不需要为每次奖励调用模型。
4. 让删牌显示循环影响、升级显示升级前后差异；结算记录关键升级是否兑现。提醒牌组厚度的代价，不强制玩家走小牌组。
5. 按成熟时间重分奖励：第一幕拿基础工具和方向线索，第二幕得到发动机和衔接，第三幕提供终结/应对/变体。发动机不能仅因高费用被推到最后一幕。
6. 先检查现有96牌，新增牌必须填补一个明确缺口，并通过重复/上下位/升级收益审核。每批少量接入，不以牌数增长验收。

### P2：让地图选择形成后续承诺

先以每幕4个选择站实现小型分支与汇合，沿用15站总长度；数据加入可达节点连接，地图图像、文字与按钮同时表达可达性。不能只绘制连线而实际仍允许跳到任意下一行。

P1试点结论以v0.9路线为基线；P2改变商店、事件和营地可达性后，必须重跑信使、医师试点，复查构筑成熟时间与资源压力，不能直接沿用旧结果。

提供可辨认的路线取舍，如获得更多构筑/遗物机会但补给紧、较稳的恢复投资但奖励少、商店和交易密集但依赖余烬。它们是路线生成模板，不是每局固定三条相同通道。

- 生成时校验存在可规划的普通战与补给路线；每条可达完整路径满足公开的首领前置规则，没有空路或隐含强迫精英。玩家自选放弃补给、冒险或花光余烬仍应承担结果。
- 单营地先保留，并让安全/冒险路线的可达性决定是否有休整机会；不把“全图有一处营地”误当成“每条路线都能进去”。补给不足是否需要改规则，依据真实消耗和失败记录决定。
- 提前提示首领主要威胁、补给位置与路线放弃项；允许玩家有计划地买道具、升级或调整牌组，而不是遇到首领后才知道必须应对什么。
- 商店先改善可用性：货架至少有实际可购买/可利用的选项，展示服务价值和未来资源取舍；随机刷新如引入必须有明确成本与上限。不能保证卖出最优牌，也不能连贯生成只耗一站的无用商店。
- 在现有借火债、封印、削弱首领基础上建立少量跨站事件链：选择、标记、代价、后续兑现与终止/到期都要记录和展示；不能只保存一个故事标记却无后续效果。
- 余烬仍只在本局使用，金币仍按现有每日上限结算；不添加新货币来掩盖现有资源用途不清的问题。

### P3：三幕与战斗形成递进

| 幕 | 主要任务 | 构筑与威胁的递进 |
| --- | --- | --- |
| 第一幕 | 建立打法、学会读意图 | 给方向线索与基础组件；清楚展示格挡、蓄力和条件攻击的应对。 |
| 第二幕 | 检验与修整 | 给发动机/衔接，敌人要求改变出牌顺序或资源安排；路线/商店允许针对性调整。 |
| 第三幕 | 兑现与决战 | 给终结或针对首领的变体；首领检查综合应对，仍有最后准备机会。 |

优先深化现有机制，暂不同时扩大战斗轮数、能量和出牌上限。敌人区别要体现在应对方法：护甲要求穿甲或持续伤害，多段要求盾量/反击安排，蓄力要求提前准备，净化要求补火或改输出，条件攻击要求选择首张牌。避免把某类流派完全免疫掉，或无预告地自动反制玩家。

每个首领建立：身份与两阶段特点 → 可读意图/切换阈值 → 至少两种可行应对 → 对应路线/奖励准备 → 战后回顾。不能只提高生命和攻击。

再复查灼烧叠层、反击多段收益、伙伴吸收与锻造上限、回声/保留跨轮效果、0费出牌价值；按启动时间、兑现概率、能量与次数、跨轮收益、敌人环境测量。12轮上限是否过度惩罚控制/治疗，作为专项问题验证，不能在缺少数据时对所有职业整体延长。

### P4a：先完成最小局后反馈

- 本局回顾：最终牌组、关键遗物、路线、发动机何时形成、关键消费与失败原因。给可靠的改进线索，缺少因果证据时不虚构“输是因为某一张牌”。

先验证玩家能否据此提出下一局尝试的方向。图鉴、解锁和酒馆展示不作为回顾上线的前置条件。

### P4b：按重玩反馈逐批加入长期目标

- 图鉴分开“已见过、已拿到、已使用、达成相关挑战”；解锁入口、记录事件、状态展示、重复达成处理、奖励与下一次使用必须齐全。
- 首批图鉴/成就只提供发现记录与展示称号，不发金币或增加战力；成就以成就ID在结果结算事务中一次性确认，重复请求不重复授予。练习可记录发现，无须发币；收集入口可跳过，不影响正常开局。
- 成就/职业课题鼓励不同做法，如一次完整回声组合、在伙伴生存下兑现命令、用不同路线通关。不要把收集做成大量重复刷局计数。
- 起手替换/职业专长属于横向选择，维持同等预算，并可免费体验；不出售永久生命/伤害/金币倍率，不让刷得久成为竞技优势。
- 每日挑战继续固定职业、起手、规则版本、种子与可用内容，横向解锁不能改变同题条件。新规则单独分榜，保留旧成绩的版本含义。
- 与酒馆连接优先展示战绩、图鉴发现和装饰性称号；已有金币结算继续事务幂等，练习仍可推进职业进阶。不为了催促游玩扩大奖励上限。

### P5：整体验收

将真实意图、牌效、费用、目标、当轮次数、延迟效果、事件代价与结果同步到文字和图片。手机上能读清下一步，危险/禁用/默认选择可辨认；强反馈覆盖实际盾转伤、治疗遗物、回声兑现和阶段切换。

减少无意义确认与反复跳页，保留真实取舍所需的操作。再检查图片清晰度、字号层级、颜色与统一术语；图像加载失败时文字操作继续可用，刷新不得重复执行状态动作。

新增世界观、事件故事、角色扩写与产品文案沿用项目Gemini起草—主agent审核—定点返修—通过后采用的流程。机制、数值、条件和状态结算由程序控制；生成的叙事不能擅自发奖励或改变规则。

## 4. 如何验收“丰富有趣”

通关率是护栏，不是总目标。不能靠随机不透明、硬克制或延长耗时制造丰富感，也不把选择分布平均当成目标。

| 检查 | 证据与判断 |
| --- | --- |
| 选择有理由 | 玩家能说出为何拿牌/跳牌、选路/跳过营地；选择对后续有可解释影响。 |
| 构筑能兑现 | 已获得核心组件时，玩家能识别并实际打出协同；不同职业/方向有不同的操作计划。 |
| 风险可应对 | 首领和关键威胁有提前信息；失败复盘可以区分决策、缺组件和数值，避免无预告硬克制。 |
| 重玩有差异 | 同职业不同种子、同种子不同路线，出现不同打法和准备过程；不是只换卡名或怪物生命。 |
| 操作不拖沓 | 记录有效决策时间、无选择回合、重复确认、掉线/退出地点；趣味不能用总局时变长替代。 |
| 不存在统治选择 | 检查强弱的情境和资源代价；不让同一牌/路线在几乎全部场景都更优，也不强行消除所有强组合。 |
| 真人愿意继续 | 询问愿否立即再开、下局想改什么；与实际重开/换职业/尝试新构筑一起看，不把主观好评当唯一证据。 |

模拟保留固定种子和现有两种策略作回归，补充会逛商店、会删牌/跳牌、会规划保留/回声的策略；测试策略变动与游戏规则变动分开记录。按职业、进阶、首领、路线和构筑成熟时间分层比较，不把不同难度混成一个总胜率。

先用小样本发现明显问题，再按实际玩家规模扩样。尚无足够真人数据的指标标为待验证，不提前制定漂亮的通关率或留存承诺。

## 5. 工程与发布边界

- 改变数值、掉落、战斗或地图规则时使用新规则版本；进行中的v0.9及更旧存档继续原规则，不能静默改写地图或牌效。
- 地图结构升级前覆盖JSON保存/恢复、可达性、首领前置、禁用按钮、地图图片及旧版路由；无路径、重复ID和孤立节点均需阻止。
- 效果/用途/触发/阶段数据保持单一来源，并有目录校验；重复牌检测结合实际战术用途和严格上下位审查，不只看字符串不重复。
- 先延续版本分发与现有稳定模块，不整体重写。新版本如要共享纯函数，保持旧规则结果不变，并用版本回放证明。
- 钱包、进阶、图鉴/成就结算继续使用幂等事务和服务器/用户隔离；失败/重试/到期不重复发奖，不丢失已确认选择。
- 新图鉴/记录字段需要明确迁移和旧记录缺字段回退；保留公平挑战与相同seed规则。后台AI不决定战斗胜负或替代规则校验。
- 记录和渲染维持有界，避免每次点击写巨量日志或调用AI；保留Cloudflare配置、绑定、Secret与现有静态资源方案，不重新引入Base64静态载荷。
- 每阶段先定向测试，再运行影响范围与发布CI；最后核验线上版本和真人交互。纯规划/说明更新只同步GitHub，不部署或升版本。
