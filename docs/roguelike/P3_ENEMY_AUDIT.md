# P3 第一批：普通敌人应对审计

运行 `node scripts/audit-lantern-p3.mjs`。审计固定直接导入 `rogue-run-v12.mjs` 与 `rogue-run-v13.mjs`，各自配对使用对应战斗与目录模块；不依赖未来可能改变的 `rogue-run.mjs` 分发器。每个动作后都 JSON 序列化并恢复存档，再继续行动。战斗决策复用 P2 两步合法动作贪心策略，路线沿用安全路线启发式，商店离开，奖励选目录第一项。

样本为8职业 × 难度0/6 × 每组2个相同种子 × v12/v13，共64局。脚本输出每局规则版本、职业、难度、种子、初始牌组与终局牌组、路线、胜负、完成节点、剩余生命、超时状态、遭遇敌人及破势触发数；下表汇总胜场与HP。模拟上限400个动作，战斗在第12回合判为失去灯火。

## 普通敌人应对差异

本批修改15种普通敌人中的4种：3种蓄力敌人新增破势窗口，镜粉舞者将最后一个固定防御意图改为看首张牌的分支意图。其余11种普通敌人数据未改；精英与首领不在本批范围。

| 敌人 | v12相关意图 | v13变化 | 应对影响与说明负担 |
|---|---|---|---|
| 巡灯学徒 `patrol_apprentice` | 攻击3 → 攻击5 → 蓄力7 → 攻击7（单段） → 护盾3 | 蓄力移到第一轮，后续基础攻击意图轮转为：攻击7 → 护盾3 → 攻击3 → 攻击5；破势阈值6，下轮攻击每段-3，最低1 | 蓄力在开场就给出明确应对窗口；一次基础斩击即可达到6点HP损失阈值。模拟10次遭遇均触发。基础攻击与护盾数值不变，只调整循环顺序。 |
| 缝影客 `a2_seam_duelist` | 护甲1；蓄力4×2 → 攻击4×2 | 阈值8；下轮每段-2，最低1 | 需要解释“敌HP损失达到阈值才破势，敌盾吸收不计；多段攻击的每一段都减伤”。模拟15次遭遇触发12次。 |
| 灰尘校时师 `a3_dust_mender` | 蓄力4×2 → 攻击4×2 | 阈值10；下轮每段-2，最低1 | 同上；阈值较高，战斗中需看进度提示。模拟10次遭遇触发8次。 |
| 镜粉舞者 `mirror_dancer` | 攻击4 → 攻击3×2 → 固定护盾5 | 最后一意图改为：首张牌含直伤则攻击4，否则获得护盾5 | 增加了攻击牌顺序的判断；需清楚提示按本回合第一张牌分类，后续打牌不会改分支。 |

破势可由任何实际扣除敌方HP的来源累计，包括主动攻击、回声与燃烧结算；被敌方护盾吸收的伤害不计。触发一次后，紧接的下一轮攻击各段分别减伤；该效果仅针对紧接的下一轮，不累积到后续轮次。按此范围，机制没有职业专属入口，但更奖励能在蓄力窗口打出伤害的牌组。本策略对三种目标敌人都出现破势；仍不能据此断言所有牌组都容易触发。

## 只读正确性核对

- v13目录只给三种蓄力意图增加阈值与减伤元数据，相关基础数值不变；巡灯学徒循环调整了起始顺序，缝影客与灰尘校时师由-3调为每段-2。v12目录没有破势字段，脚本固定按版本导入，避免v12意外读取新目录。
- 战斗按敌方HP实际损失累计进度，因此敌盾吸收不计；主动伤害、回声伤害和敌方燃烧结算都进入同一累计量。达到阈值后只登记一次，后续攻击每段按-3或-2结算且至少为1。蓄力结束后的破势状态会跨动作JSON恢复，并在紧接的攻击意图消费。
- 镜粉舞者分支根据首张牌类别，在结束回合时选择攻击4或护盾5；本批同时完成15种普通敌人的战术特征与动态意图UI提示，审计脚本仍只对4种数值变化做规则与模拟核验。精英和首领不在本批范围。
- `node --test rogue-v13-combat.test.mjs` 的9项测试通过，覆盖目录隔离、蓄力开局与循环、护盾不计、阈值与每段减伤、燃烧、回声与JSON恢复、难度加成及运行服务边界。

这组固定种子和自动策略只用于机制覆盖、状态恢复与明显行为差异检查。它不是真人游玩数据，也不能证明趣味、职业平衡或总体胜率。镜粉舞者分支的实际遇见情况不足以单独评估玩家理解度；建议后续真人试玩重点确认分支意图说明与破势触发反馈是否容易读懂。
