# 灯下迷城 · 第一阶段公共规则

日期：2026-10-10（Asia/Shanghai）。规则版本提案：lantern-core-v0.1。
本阶段完成设计与纸面演算，不接入Worker、不发布游戏、不调整现有经济。后续内容模块必须引用本规范；数值仅为可演算原型，尚未通过实机平衡验证。

## 1. 范围与基线

- 单人、3幕、每幕2个分岔房间和1个固定Boss，共9个已选站点；每个分岔只进入一个房间，不是两个都打。
- 一次选择推进一个阶段；战斗每轮抽3张、选1张，未选两张弃置。基础角色提灯旅人：最大生命30。
- 当前运行基线beta.47；每日总收入150包含手动到店礼20、合格多人游戏和伙伴奖励，伙伴自身20子上限。欢迎60为一次性来源，不在肉鸽开局重领。
- 旧肉鸽30币通关/60币子限额仅为未接入提案；本阶段固定结算接口和退出资格，不确认最终发币金额/评分公式。
- 独立游戏副本，不占频道多人牌桌、不改真实建筑、不替代伙伴同行或持久钱包；不每回合请求模型。

## 2. 一局的阶段

| 阶段 | 玩家可以做什么 | 下一阶段 |
|---|---|---|
| HOME | 看规则、开始普通局/当日挑战、继续已有局 | ROUTE或已有阶段 |
| ROUTE | 二选一路线，显示房间类型/风险/奖励方向 | ROOM或BATTLE |
| ROOM | 按房间选择休息、购物、事件、开宝藏；商店可离开 | REWARD或下一站 |
| BATTLE | 从本轮三张牌选一；查看牌/遗物/敌意图 | BATTLE、REWARD或RESULT |
| REWARD | 从固定候选选一个，或明确跳过 | ROUTE或CHECKPOINT |
| CHECKPOINT | 第一/二幕Boss后：继续或撤离 | ROUTE或RESULT |
| RESULT | 看结果、实际到账、重新开局或返回大厅 | HOME |

第一站/第二站是分岔，第三站Boss自动进入，不再抽随机替代房。房间只有一次通关标记；消费、选奖励、跳过奖励都不能让同站多推进一次。奖励未处理前不能选下一站。
第三幕Boss胜利后自动准备通关结果，不出现第4幕或撤离按钮。Boss候选遗物只在第一/第二幕出现；最终Boss不强迫玩家选择已经用不上的遗物。
HOME只负责找到一局，不是存档里的进行中阶段。进行中同服务器/同用户最多一局，同服跨频道继续；每局归属服务器固定。开始新局不能覆盖旧局，先继续或明确放弃。其他服务器不能操作、领币或续接这一局。

## 3. 房间完成与导航

- 路线候选在进入ROUTE时已保存；查看/刷新/恢复不能换房、重抽奖励或敌人。选中后未选支路不可再进入。
- 房间生成先保证第一幕首个房间为普通战斗教学，两条支路可以是不同敌人，但不能首次就出收费商店/必死精英。
- 每幕两个非Boss房保证至少一个非战斗选项；全局不能生成需要花钱才能离开的房间，商店买不起时仍可离开。
- 非战斗房处理完成立刻消耗该站；战斗胜利后进入奖励，选择/跳过后消耗该站。房间失败直接终局，不再给下一站奖励。
- 事件预先显示资源代价和确定后果；未知奖励可隐藏，但代价不能在玩家确认后增加。首批事件不生成生命为零的必选代价。
- 篝火治疗/删牌二选一，各房仅一次；删牌时牌组至少保持3个实体，不可无牌开始战斗。商店限本房访问，购买项/价格/是否售罄持久化。
- 进入Boss前清理上一场战斗的临时护盾/灼烧/回声等；生命、牌组、遗物、余烬跨房保留。未开始下一战前新增牌生效。

## 4. 抽牌与不可重抽

初始牌组6个独立实体：斩击×2（伤害6）、格挡（护盾8）、突刺（无视护甲伤害4）、抢攻（先自伤2，再伤害8）、包扎（恢复3，不超最大生命）。
每场战斗开始把当前牌组复制为战斗牌堆，独立洗牌；对同一局/同一战斗重进面板不重洗。顺序、手牌实体ID、弃牌堆和轮数一起保存。
每轮抽3个不同实体，牌堆不足时先抽剩余牌，再洗此前弃牌补足；已经抽入本轮手牌的实体不能再次抽入。同名的两个斩击是不同实体，可同时出现。
选择的牌结算一次，随后三张牌都入弃牌；未选择牌不触发“打出”效果。攻击过时按钮先返回当前手牌，不用旧牌替新牌。重绘图片不改变随机序列。

## 5. 回合与终止顺序

1. 轮开始：清理过期状态，兑现已保存的护盾保留；敌方意图固定并显示，此时只预告，不执行伤害。
2. 执行待发生的回声，仍按其原代价结算；若战斗在此结束，不再要求选牌。
3. 抽3张并保存完整回合；展示意图/剩余回合/每张牌的效果与代价。
4. 选择1张；先付自伤代价，生命归零立即失败，该牌剩余效果不执行。
5. 执行牌的明列效果和有限触发。每个伤害包后先判玩家生命，再判敌方生命；敌人已倒下不继续行动或触发新的反伤。
6. 若双方仍在战斗，执行本轮敌意图。护盾先吸收普通伤害；护甲减伤在护盾前，无视护甲牌跳过护甲但仍消耗护盾。
7. 回合末依次处理玩家灼烧、敌方灼烧；灼烧无视护甲与护盾，每次扣当前层数后减少1层。每次扣血立即检查终止，死亡不能被后续治疗/反击救回。
8. 剩余玩家护盾按遗物保留规则保存（默认0）；临时护盾清理，再进入下一轮。

新施加灼烧在本轮末第一次扣血，所以敌人仍可能先行动。永久生命不自动在房间/章节开始补满。
一旦确认胜利，不再执行未到的敌行动、反击或回合末扣血；一旦确认失败，不允许后续治疗/灼烧杀敌把结果翻成胜利。将来若某个同一效果确实造成双方同时归零，统一先判玩家失败，不算击败Boss。多伤害效果必须规定包顺序，不靠随机遍历决定胜负。
玩家护盾上限30，灼烧层数上限20；实现时这些上限是规则版本参数，不在客户端自由改变。敌人的架盾是明示“保护下一轮”的意图：护盾跨到玩家下一次出牌，随后到敌方自身下次行动前清零；不能在架盾刚结束时清掉，让架盾失效。
每场最多12轮，回合末已执行所有状态仍未决胜则“失灯”，按败退结果结束本局。剩余轮数始终可见；防止永久治疗/防守拖到无限生命或刷触发分。目标普通战2—3轮、Boss4—6轮是内容设计目标，不是硬性胜利要求。

## 6. 触发与三流派边界

- 事件队列按固定顺序执行；遗物按目录优先级、同优先按获得顺序。重启后顺序不变。
- 倒燃蜡烛：打出含灼烧的牌额外自伤1，纳入步骤4代价；之后施加的灼烧层数翻倍并截上限。额外重放也支付原/遗物代价。
- 刺背披风：敌方单次攻击被护盾吸收至少1点后反击4，每次敌攻击最多一次；若该攻击已使玩家死亡，不触发反击。反击本身不再触发双方反伤链。
- 旧门闩：回合末将剩余护盾的一半向下取整保存；主动攻击牌的直接伤害-2，最低0，不降低灼烧或反击伤害。下一轮保存值与本轮新盾相加后截30。
- 回声铃：每场首次真实选牌排队，下轮额外执行同张效果；重放不消耗牌、不再触发首次选牌、不再排队自己。战斗结束即丢弃未执行回声，不带到下一房。
- 不把“触发一次遗物”本身计分；不存在对无限触发/治疗的计分奖励。
- 其他遗物/职业设计必须明列触发事件、代价、次数上限和持续范围后才能进入内容目录。

## 7. 终局与奖励契约

| 结果 | 可以触发的位置 | 奖励资格 |
|---|---|---|
| CLEAR | 第三幕Boss及其战斗效果全部结束 | 待定通关奖励 |
| RETREAT | 第一/第二幕CHECKPOINT明确确认 | 已击败Boss对应撤离奖励 |
| DEFEAT | 战斗/明确事件生命归零，或12轮失灯 | 待定败退部分奖励 |
| ABANDON | 进行中任何可操作阶段，本人二次确认 | 不发币，不当撤离/通关 |
| EXPIRED | 72小时无有效游戏动作后 | 不发币，不当撤离/死亡 |

只有成功选路、选牌、购物、处理房间/奖励、继续章节重置72小时活动时间；打开详情/刷新不延长。此期限是设计参数，实现用按需检查/单次到期调度，不持续轮询。
终局首先固定唯一结果和已完成节点，保存不可再战的状态；随后准备奖励凭据/评分记录。到账失败保持RESULT的“结算待重试”，不重开战斗、不清除应得结果。重试不能改变种子、击败Boss或原结束日。
RESULT属于已结束局，不占进行中局名额；结算待重试也可开始下一局，但旧结果/结算记录必须独立保留。打开旧结算卡只处理旧runId，不能覆盖新局或把新局的奖励写入旧流水。
每局唯一结算ID。已有TavernService按同服务器/玩家入账，日总额含到店礼/伙伴/多人游戏；消费不会恢复限额，不借欢迎金给每局开局金。日归属提案固定为开局北京日，与现有伙伴相同；最终接入前核对过期历史日记录策略，不能用恢复/跨日突破任一日限额。
副本余额与钱包分别保存；余烬/未领取奖励候选不能兑换。金币奖励只在终局一次入账，不先发后回收。排行榜重试独立按runId去重，不能因排名服务失败回滚已完成钱包交易。
候选30币通关/60币肉鸽子上限/评分公式统一留给经济阶段依据模拟校准，本阶段没有确认它们是线上参数。

## 8. 每日挑战与版本

普通局随机种子；当日挑战固定北京日/服务器赛事/规则版本/初始配置。每个房间、候选、牌堆和敌意图分别由独立随机子流决定；改某场抽牌不能推移后续地图/奖励。
每人当日可反复挑战取最佳；创建次数本身不发奖励，不把公开种子当秘密，不公开尚未到达的候选/牌堆。对同一人同一活动局恢复只读原保存结果。
分数不依赖真实点击速度。严格同题榜只比较相同初始配置、日期、种子组和规则版本；运行期间更新内容仍按开局版本继续，新规则另开榜组。完全同分并列。
显示昵称用于展示，所有动作权限来自账号/服务器/局ID/版本/阶段；每日英雄和牌组统一，永久外观解锁不能影响能力。
规则内容至少保留到所有采用该版本的72小时活动局终结，已终结的历史结果仍按原版本展示；更新版本不能让旧局临时变规则或卡住。

## 9. 最小共享数据

runId、ownerUserId、originGuildId、mode、rulesVersion、seedGroup/startDay、phase、actIndex、slotIndex、选中路线/已完成站点、HP/上限、牌组实体、余烬、遗物获得顺序、战斗抽弃/手牌/意图/状态/轮数、固定奖励候选、操作版本、最后有效动作时间、终局原因/完成节点、结算ID/待处理/已到账金额、排行榜待发送标记。
不在图、公共状态、AI主持中泄漏手牌堆顺序/未揭晓路线奖励/余额；UI读当前状态不算一次游戏动作。
每个有效动作必须同时更新阶段/资源/版本，失败不消耗资源也不推进；重复交互返回已处理结果，非本人/跨服/过时版本拒绝。

## 10. 第一阶段验收

纸面样例必须覆盖开始→两个房间→Boss→奖励→CHECKPOINT→继续/撤离，以及战斗死亡、代价致死、失灯、主动放弃、到期、结算失败与重试。样例的固定手牌是演算输入，不宣称来自实机随机生成。
需要展示一组合法战斗抽弃追踪与至少一次遗物触发/护盾/灼烧数值计算，找出死后行动、重复奖、重抽和无限防守漏洞。尚不做全牌池、三幕内容数值平衡或实机UI验收。
