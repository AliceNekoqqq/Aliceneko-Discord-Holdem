# P3 第二批：精英机制审计

运行 `node scripts/audit-lantern-p3-elites.mjs`。脚本固定导入 v13/v14 战斗模块与各自目录，直接用 `beginBattle` / `battleAction` 跑真实战斗循环；不生成或读取随机全局路线图。每个版本都用八职业的初始牌组、职业起始遗物、难度对应最大生命、同一对战斗种子；不额外给予道具。合法卡牌/目标/道具/结束回合进入两步贪心选择。每个战斗动作后都 JSON 序列化恢复，直到胜负或12回合；每局完整动作、动作前后关键状态与新增日志以 JSON 输出。

固定样本为8职业 × 难度0/6 × 两名精英 × 每组2个配对种子 × v13/v14，共128场独立战斗（每版64场）。脚本在开跑前断言两版职业内容完全一致，并在忽略目录版本标签后断言全目录只有 `cracked_sergeant` 与 `chain_duelist` 两条敌人记录不同；也断言每局 battle state 的规则版本正确。该样本是机制覆盖与明显数值极端检查，不是真人平衡或趣味数据。

## 规则核对与验证

- v14 目录保持巡官基础护甲3；其主阶段和半血阶段的每个蓄力意图都带护甲-3、破势阈值8、下一紧接攻击每段伤害-4，因而蓄力回合护甲归零。破势按敌方实际生命损失累计，敌盾吸收不计；蓄力结束后若切换到非攻击意图（包括半血阶段转换出的守势），破势取消，不排队到后续攻击。固定样本确实经过蓄力窗口、触发破势并实际看见一次性攻击减伤。
- 镜链斗士主阶段首意图与半血阶段首意图均为首牌条件分支。首张牌含直伤锁定三段攻击（主阶段4×3、半血阶段5×3），首张牌不含直伤或未出牌则锁定单段攻击（主阶段7、半血阶段9），后续出攻击牌不会改变已锁定分支；战斗结束回合依据已锁定的 `firstCardKind` 结算。脚本 transcript 保存每个动作与该锁定状态，阶段分支样本覆盖两种首牌类型。
- `node --test rogue-v14-combat.test.mjs`：16/16通过，覆盖精英目录隔离、护甲窗口、破势实际损失阈值、跨阶段取消、难度/危险/债务预告、链斗士主/阶段双分支及 JSON 动作边界。独立128局审计脚本通过目录范围、规则版本、动作上限与机制触发断言。

该审计不运行整条冒险，故不评价路线、奖励、商店或长期构筑；每职业每敌每难度仅两种子，不能代替真人手机呈现、选择理由、趣味和总体平衡验证。
