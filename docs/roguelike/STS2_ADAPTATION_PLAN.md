## 2. 优先测试的玩法调整

| 模块 | v0.1对照 | v0.2原型方向与目的 |
|---|---|---|
| 回合资源 | 抽3选1，无牌费 | 抽4、每轮2能量、至多主动打2张实体；允许先防守再攻击或铺状态再攻击 |
| 交互 | 点击一张即走完一轮 | 点一张立即结算并更新同一私密面板；可出第二张或结束回合；敌人只在玩家结束后行动 |
| 成长起点 | 先过Boss才稳定有遗物 | 开局选一个轻量构筑遗物；第二/三幕起始再选章节遗物，使玩法在第一幕就有侧重 |
| 章节奖励 | 前两Boss给遗物再检查点 | 将这份遗物移动至下一幕开始，先检查点继续/撤离；不额外加发一份，终Boss无无用奖励 |
| 篝火 | 治疗或删牌 | 先测试治疗/升级二选一；删牌保留商店/明确事件，避免一个房间同时补全所有需求 |
| 地图节奏 | 固定9站 | 先验证9站的成长密度与时长，再决定是否加站；至少首Boss前有新牌和初始遗物可发挥 |
| 数值 | 单张伤害与固定牌序 | 先定每轮资源、牌组循环、敌行动次数和每幕损血预算，再定单卡/敌人参数 |

这是Discord轻量原型的设计选择，不是尖塔2本身的规则。2能量在轮开始重置、不跨轮存储。初批避免0费牌、循环抽牌、回能、额外回合；费用先用1/2两档，之后再评估0费与2张上限是否限制合理组合。

每张牌按顺序扣能量、支付自己的生命代价、执行效果、检查终止；不能因预选两张提前扣未执行第二张的自伤。主动打出即移入弃牌，剩余手牌在回合结束弃置；保留实体ID、旧按钮和版本规则。回声额外重放仍使用v0.1有限触发，不花第二次能量、不算主动出牌数，但照付生命代价；原型暂不提供回复能量/抽牌型回声。满2张后自动结束；少于2张可明确结束，无牌或没有合法出牌时自动结束。不因暂离自动替玩家出牌。

改抽4需同时把最小牌组从3改为4；未到4实体不得删牌。开局赐福及章节赐福是ROOM的子类型，不凭空插地图站数。继续检查点后才进入下一幕赐福，撤离者不先领下一幕遗物。ROOM赐福选取后才进入ROUTE；固定候选与跳过规则需在v0.2公共规范明列。

## 3. 数值标定方法

固定同一手牌可比较三个选择：以测试用1费6伤斩击、1费5盾格挡为例，2能量允许双斩击12伤、斩击+格挡6伤5盾、双格挡10盾。面对7伤、剩12HP的无盾敌，双斩击直接结束战斗；面对20HP敌，攻防组合则造成6伤并受2伤。这只是一个局面，不是普遍最优解，更不是把尖塔数值自动设成我们的最终牌值。

若沿用旧普通敌12HP，双斩击可能一轮结束，旧Boss20HP与旧三轮样例也不能直接迁移。敌人不统一乘二：根据可用手牌、状态收益、盾牌占用的伤害预算、击杀轮数和意图周期重算。

评估牌的价值时分别记录即刻伤害、防止HP损失、未来回合收益、抽牌/能量成本、永久自伤、升级幅度；不把1伤害和1治疗视为可永久互换的同单位。突刺需有护甲敌人体现条件价值；抢攻看是否减少敌行动，不仅看多2伤；包扎需测试拖延净回血，优先比较每战有限使用/消耗方案，而不是靠12轮上限宣称问题已解决。旧遗物盾上限/灼烧上限及回声次数都随出牌制复核。

## 4. 下一轮验收

1. 明列1角色初始牌组、费用、升级及每战使用范围，准备攻击/防守/灼烧三种构筑；新牌先解决流派组件，避免只有更大伤害数字。
2. 准备普通、有甲、精英和Boss样本，覆盖相同手牌下不同出牌顺序、自伤致死、状态击杀和护盾反击。Boss至少走完一轮意图周期，不能只靠手工安排好牌跳过机制。
3. v0.1/v0.2先在同一敌人池/起始牌池做规则对照；随后给v0.2独立校准的敌人作体验验证。初始种子可相同但抽牌数不同，不能声称两制手牌序列完全相同。
4. 统计多组种子的战斗轮数、HP损失/分位数、失灯率、牌被选率、关键牌出现时点、治疗净收益；记录每局奖励次数、牌组尺寸与每回合真实点击数。策略覆盖贪伤、保血、条件牌、流派构筑与跳过弱奖励；不只测试一种聪明策略。
5. 纸算/程序模拟/真人手机试玩分开报告；一幕算例走通仅证明流程合法。通关率、局长、适当敌强与币收益目前均未测定，经济最后再按实际体验调整。
