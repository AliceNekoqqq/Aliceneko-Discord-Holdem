## 接入说明（给执行者）

1. 不要直接改已生成的图集或 Base64；新增走源表 + 生成脚本。
2. 数据源：`tavern-auction-data.mjs`、`tavern-auction-large.mjs`、`assets/auction-art/prices-v1.json`、`drop-weights-v1.json`、`large-props-v1.json`。
3. 必须把 `catalogVersion` 提到 **8**；旧局按各自版本池与价格结算。
4. 美术：256×256 真透明 PNG → WebP，与现有 204 件同一套写实 3D 风格；红色件要有可近看的材质细节（切面、火彩、包浆、釉面）。
5. 概率：新增件必须用服务端容量感知模型重算图鉴的「同色/每件/每仓」，不能套独立抽取公式。
6. 大件：仍受 6/9/12 格、每仓最多 1 件、按区 15/25/40/55% 尝试镇仓位约束。
7. 红色件权重单独审：新增 6 件传世红若按普通红色件权重投放，会稀释既有稀有件；建议给 0.2–0.4 倍权重并在模拟里复核。
8. 测试：`npm run test:tavern`、`npm run test:worker`，并核对图鉴计数与旧局兼容。

## 关于「现实产品」的边界

本表用**品类与年代**来指代现实物件（银壳猎表、旁轴相机、留声机），**没有直接使用品牌名或商标**：这个项目对外的定位是原创改编，写真实品牌容易踩到商标与授权问题。
如果你就是想要「劳力士」「徕卡」这种直呼其名的版本，告诉我，我按你的口径改一版，并在文档里注明来源与风险。
