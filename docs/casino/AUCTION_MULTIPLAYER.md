## 玩家流程

1. 同一 Discord 服务器的玩家通过六位房号加入；至少两名真人，其余位置由 NPC 补位。
2. 各自选择眼力并准备。客人换角色后需要重新准备，房主的开局按钮自动更新。
3. 开局一次性托管每人的入场费与预算。任何一个钱包不足、生成失败或后续写入失败，整次操作回滚。
4. 每个座位拥有独立、持久化的技能线索。网页只收到本人的线索、估值与遮罩棋盘；NPC 使用自己的线索和所在区域的大件估值模型。当前轮其他人的报价在开牌前保密。
5. 五轮内满足提前成交条件即落槌，否则继续下一轮。每轮60秒，全真人提交时立即开牌，超时未提交按0处理。同价按开局公布的优先顺序。
6. 赢家支付成交价，其余预算退回；未拍中只付入场费。真人赢家的藏品先以锁定状态入仓。
7. 全桌共享逐件揭晓。任何参与者可开始、暂停、单件或全部打开；进度由服务端时钟决定，多人查看不会加速。刷新或断线后恢复同一进度。
8. 全部揭晓后解锁藏品，展示成交价、藏品预估总值、个人单仓盈亏与现金变化。个人仓库可恢复未完成的联机开仓。

赢家盈亏 = 藏品总值 − 成交价 − 入场费。未拍中者盈亏 = −入场费。现金变化不包含未出售藏品的价值。

## 服务端契约

- 房号用于邀请；独立16位十六进制 `room.id` 识别具体对局。房号再次使用时，财务流水、库存来源与请求回执仍属于不同对局。
- `GET /auction/api/room?guild=…&roomId=…` 返回调用者有座位的房间。省略 roomId 时恢复当前房间。GET 复用60秒成员证明；所有 POST 仍校验 CSRF 与实时 Discord 成员身份。
- `roomRole/roomReady/roomStart/roomLeave/roomReveal` 必须携带 roomId；`roomBid` 还必须携带 round、requestId、bid。重复 requestId + 相同报价返回现状，不写下一轮；不同内容拒绝；过期轮次拒绝。同一轮仍可修改自己的报价。
- 单次房间操作包在 SQLite `transactionSync` 中，托管、报价、退款、库存和状态一起提交或回滚。每人每局最多256个不同报价请求，回执随房间清理。
- 新局冻结 catalogVersion=8、dropVersion=5、skillVersion=2、warehouse/items/board/infos；线索只在开局或换轮时推进。
- 新局揭晓间隔900ms，首次开始立即揭晓一件；随后按经过时间追赶。单件/全部操作需要当前 step，自动揭晓运行时不可叠加手动推进。
- 未完成揭晓不可离开或创建另一联机房间。完成后离开只移除本人，不清除其他人的结果；新房间会解除本人旧的已完成房间座位。
- 等待房间30分钟、其他房间2小时后在后续房间请求中清理。进行中退回托管预算；已成交但未揭晓的藏品全部解锁，避免永久锁仓。没有新增 alarm 或绑定。
